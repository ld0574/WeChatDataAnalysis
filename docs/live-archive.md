# 持续归档与搜索

运行仓库根目录的 `Start-LiveArchive.cmd`，打开 <http://127.0.0.1:3001/archive>。
需要保持后端进程运行；它从正在运行的微信只读采集数据。当前功能属于源码运行版，未重新打包到已安装的 Electron 程序中。

配置位于本机 `output/live-archive.json`（不提交 Git），字段如下：

- `enabled`：是否随本地后端启动采集。
- `source_account`：已有数据库密钥的账号名，配置中不写密钥。
- `source`：微信的 `db_storage` 目录。
- `baseline`：已经完成的解密快照，必须保留其中的数据库和搜索索引。
- `baseline_manifest`：基线解密时记录的源文件签名清单。
- `storage`：新增记录、游标、搜索索引和媒体的独立存储目录。
- `voice_model`：要求使用的本地转写模型；当前配置为 `qwen3-asr-06b-hf`，未就绪时仅保留音频并重试。
- `voice_batch_size`：Qwen GPU 每批 1、2 或 4 段，未配置时为 1。按实际显卡和语音样本评测后再调高。
- `voice_gpu_precision`：`auto` 使用模型默认 GPU 精度；`float32` 在 GPU 上使用全精度计算，显存占用更高，不会回退到 CPU。
- `voice_asr_paused`：仅暂停文字转写，消息采集、原始音频保存和播放转换继续运行；修改配置后重启后端生效。

基线以只读方式打开。后续变化写入独立 SQLite 数据库，原始字段、解析结果、FTS、媒体任务和采集游标在一个事务内提交。每张表从小到大补采，不会因为单轮页数限制跳过积压；服务重新启动后从提交过的游标继续。

去重使用会话和服务器消息 ID；没有服务器 ID 时使用数据库、表名和本地 ID。服务器 ID 后续补齐会合并已有记录。编号复用时保留不同消息，消息内容变化保留旧版本。前端合并基线和新增搜索结果，并过滤同一消息的重复命中。旧版本保存在数据库 `revisions` 表中，目前界面显示当前内容。

采集还会分批核对水位以下的记录，以补齐迁移进入的历史和内容变化。源库持续变化时无法声明一个永久完成的实时快照；页面显示已发现表数、已核对表数、心跳及错误。核对未完成时不应把采集数量当作完整性证明。微信删除后才启动采集、微信从未下载的媒体，以及电脑上从未存在的消息无法从本机恢复。

核对按持久化的最近服务序号轮转，每张候选表每轮最多一页（500 条）。序号、消息变化和页游标一起提交，大表和持续变化的分片不会占住整轮预算；重启和表枚举顺序变化不影响轮转位置。页面显示当前源文件版本已核对、待核对和核对中的表数。微信继续写入时版本覆盖数字可能变化，不能将一次心跳理解为全部历史已完成核对。

图片和语音分别排队处理，失败后保留任务并按退避间隔重试。图片默认转为 WebP，长边不超过 1920 像素，质量 82，保留透明通道；动图保留动画原文件。语音读取覆盖普通 `media_*.db` 和业务 `biz_media_*.db` 两类分片，保留 SILK 原始音频和可播放副本，并用本地 GPU 模型转写。语音文字在事务中加入搜索索引，不会发往云端。媒体存储盘不足 5 GB 时暂停媒体写入。后台按已知消息补媒体，不扫描整个附件目录，也不自动从远端补下载。

语音使用三个独立的持久化阶段：原始音频落盘、播放副本转换、文字转写。原始音频刷新到磁盘并原子替换后才提交阶段状态；文件已写入而提交前退出时，会复用已有文件恢复。播放和转写分别重试，一条难以识别的语音不会阻塞后续音频保存。新增或变化消息优先于历史回填，即使消息本身的日期较早。旧版本任务首次启动时迁移，沿用已保存文件、转写结果和失败退避时间。

Qwen 批量路径先预取解码，再按分段长度分组，结果始终映射回原任务。某段无效或整批显存不足时拆成小批及逐条恢复，成功结果独立保存，失败结果保留任务；不会将截断输出当作成功。批量缓存仍按原音频哈希、消息 ID、模型版本和语言隔离。

在 RTX 2080 Ti 上，12 段合计约 183 秒的本地样本（模型预热后）测得：默认精度单条约 70 秒；全精度单条约 54 秒、批量 2 条约 33 秒、批量 4 条约 21 秒。全精度批量 2 条与全精度单条在该样本中忽略标点后文字全部一致；批量 4 条存在文字差异，因此本机选择 `float32` 和批量 2。该结果是样本回归和本机性能测量，不是所有显卡的速度或语音准确率保证；其他硬件默认仍为批量 1。

历史媒体仍在逐步排队；源文件缺失或密钥不匹配会显示等待重试，不能将文字归档完成理解为媒体也全部保存。历史队列有容量限制，避免一次入队大量任务占满磁盘。搜索结果中的媒体优先处理，保存完成后页面自动显示，无需重新提交搜索；反复查看不会重置真正失败任务的重试退避时间。

语音历史回填的容量限制只计算等待获取原始音频的任务；已保存音频但尚未转写的记录、原音频缺失的重试记录不会堵住后续原音频的发现和保存。空间低于预留值时暂停历史媒体入队与媒体写入，保留游标，消息采集继续。

每五次媒体处理预留一次给已到重试时间的任务，避免历史队列持续补充导致重试饥饿。Qwen 输出达到上限且未生成结束标记时，会自动缩短音频分段继续使用同一模型；仍失败时保留音频和错误，不保存截断文字。本机语音库缺失的音频需要先在微信中下载或恢复备份，单纯重建搜索索引无法恢复音频。

接口：`GET /api/archive/status`、`GET /api/archive/search?q=关键词`、`POST /api/archive/media/status`、`GET /api/archive/media/文件名`。搜索页面的历史基线目前固定，只有后续覆盖层增量写入；它不是对原有 923 万条索引的重复重建。
