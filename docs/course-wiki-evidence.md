# Wiki 课件证据

Wiki 写作计划现在可以混合视频窗口与课件片段。课件选择使用 `document`（数据库正整数 ID）、`revision`（提取版本 SHA-256）和 `text_sha256`（完整片段 UTF-8 字节 SHA-256）。这些值必须与当前活动记录完全一致，不会自动改选新版本或截断长片段。

`render_page` 是可选的 PDF 页码，只适用于原生文字片段，必须与其完整 locator 中的页码一致。程序从保留附件读取对应 PDF，校验容器与 ZIP 成员哈希，再使用本机 Poppler 渲染该页；不会重新做 OCR 或改动生产提取数据库。图像由内容哈希去重，渲染记录绑定源文件、页码、渲染器版本与缩放策略。模型生成文章时不执行课件代码。

已有 OCR 图片则沿提取元数据读取，只允许归档内 `document-visuals` 中的图片。所有 Wiki 原图保留在 `wiki/media`，只接受有大小、像素、完整解码与哈希校验的静态 PNG/JPEG/WebP；HTTP 接口不能访问任意磁盘路径或执行 SVG。图片与文字会保留到文章的固定证据包，重提取后旧文章继续可读。

冻结时检查当前提取版本及父来源链，并验证保留附件字节。旧原生记录可能没有历史 `document_version_metadata`；此时明确记录 `metadata_basis=current_revision_snapshot`，仅固定本次观察到的当前元数据，不能冒充已经存在的历史收据。已有历史元数据与当前版本矛盾时拒绝冻结。

单证据包最多选 16 个课件片段，来源总文字受 3,200 字符与 11,500 字符来源 JSON 上限约束。长文章使用下述分章计划，各次模型调用仍保留这些限制。片段引用不表示全文、整份课件或关联课程已完整整理。

页面按具体页码或位置展示课件出处；每章可展开实际引用的课件原页，对照原文和代码。正文配图与出处原图分开统计，不能把可展开的原页算成模型已完成图文组织。模型未选用代码或配图时仍如实记录缺口。

整理进度单独统计文章实际引用的课件片段和附件路径，不增加视频课程覆盖数。冻结版本与当前数据库或保留附件清单不一致时记录问题，旧文章不被静默改写。覆盖快照仍不能证明语义正确、全文覆盖、独立备份完成或允许删除视频。

## 来源对照与历史

本机来源对照可加 `--single-targets`，每次只核对一个主张或答案，避免同批不同段落交叉选择出处。该策略有单独的配方指纹与断点；旧批次的失败尝试和三次预算原样保留，逐字引句校验保持不变。

每个完整报告保存到 `wiki/review-jobs/<job>/receipt.json`，同一配方后续续跑不能覆盖第一次完成的时间或结果。切换模型或策略前，程序先校验并保留现有完整报告，再更新当前报告。历史报告可通过 `/wiki/api/review/<article>?job=<job>` 读取，仍须校验文章、配方、逐批请求及引句。旧报告兼容读取。

这仍是模型辅助对照。其他本地模型或多次对照的一致结论不能自动标为独立语义验收。

定点修订可重复指定 `--review-job <历史任务 ID>`，最多绑定四份完整的前向核对报告。程序重新验证每份历史报告，合并任一报告标出的非支持项，在每项请求中保留所有指定模型的意见（包括支持与不支持的分歧），不按多数票决定事实。文章来源记录固定报告任务 ID 和内容指纹；发布前再读同一组历史报告，任一报告变化则拒绝发布。参数顺序不影响准备记录、断点或任务 ID；显式历史输入不依赖可变化的“当前报告”指针。未指定此参数时，原单报告配方及失败预算保持兼容。可与 `--omission-job` 共同使用，`--prepare-only` 则先在 CPU 上冻结合并后的完整请求，且不调用模型。

## 从遗漏报告补写与修订

`course_wiki_revision --omission-job <历史任务 ID>` 可显式选择最多四份完整遗漏报告，与前向来源对照共同决定修订目标。开始前使用报告读取器重新校验固定文章、原文、配方、范围、请求、阶段结果及汇总，报告内容指纹写入新稿的来源记录；发布前再核对同一份历史报告。未指定遗漏任务时，既有修订配方、断点和失败预算继续兼容。

模型判断“部分讲到”的范围优先修订同章实际对应的正文；没有对应解释的遗漏、无法判断项或仅有代码的项，会补写该章的一段说明。多个问题可合并到同一个稳定的原段落或补写目标，但不跨章挪用来源。补写与省略在原段落删除完成后按固定章节位置处理，避免索引漂移；原样代码不作为遗漏修订的可编辑目标。替换内容须引用每条遗漏线索对应的原文来源，仍须通过章节范围、固定代码、自测、重复段落等整篇检查。

请求提供完整固定原文、原段落、同章已有正文和模型检查线索；模型意见与已有文章都不能当作事实来源。超过 16,000 字符请求上限则拒绝处理，不截断原文或省略问题。材料不足时允许写明缺口，不能标为已经补齐知识。模型无遗漏、已修订、引用有效，都不能代替新的来源核对、遗漏检查和独立语义验收。

`--prepare-only` 在 CPU 上冻结实际修订请求和两类报告绑定，保存到本机 `wiki/prepared-revisions`，不解析在用模型权重、不调用模型，也不发布新稿。准备记录按内容指纹去重，现有同名记录被修改会拒绝覆盖。其状态明确为 `prepared_no_model_calls`，权重版本在实际生成时另行绑定，不能把准备完成报成文章修订完成。

## 长材料与原样代码

`course_wiki_planning --root <归档目录> --video <课程ID>` 为一门已发布来源课准备一篇主题计划。模型读取完整片段目录，程序再读取所选片段的完整原文并调用 `prepare_plan` 校验；目录不能作为正文事实依据。模型只安排四章及各章完整学习目标，程序按章派生四道自测的范围，避免重复或越界题目编号。材料不足可明确跳过；未选片段及不适合本次写作的片段仍在收据中保留，不计作整课覆盖。

选题指针固定来源、模型、完整目录和当时已有主题。文章目录后来变化或自身文章发布后，续跑仍使用原配方、断点与三次预算，不能凭目录变化重新获取尝试次数。超出目录上下文限制时明确停止，不截断目录。8 项回归覆盖自测派生、未选来源、重启复用、失败预算、GPU 等待、资料不足、完整原文冻结失败和不安全指针。选题完成仅为 `prepared_for_writing`，之后仍需正文生成、来源支持及逐来源遗漏核对。

`course_wiki_synthesis` 接受显式编辑计划：概述来源、4–8 章各自的标题与职责、各章完整原文选择、3–5 道自测的章节范围，以及可选的代码摘录位置。每章独立冻结原文，合并证据最多 96 个来源、26,000 字符原文及 300,000 字节来源 JSON；每次请求上下文最多 15,000 字符。超过限制拒绝处理，不以摘要替换原文，也不把其他章节的模型稿作为事实来源。

来源枚举按本次调用的证据范围约束。文章发布、读取和定点修订再次检查概述、章节、自测的引用范围，章节标题不能漂移。计划内代码由稳定来源编号和字符范围固定，程序逐字填回，后续修订不能改变选定摘录。模型负责解释材料中的作用与条件；页面明确提示代码没有执行验证。编辑范围说明进入资料缺口，不能把部分文件导读标为整个工程已覆盖。

各阶段复用 GPU 互斥、请求指纹、断点与跨重启三次失败预算。缺章、缺题、越界引用或代码变化都阻止发布半成品。结构通过仍发布为模型草稿，语义复核和全文覆盖保持未验收。

修订输出将替换与省略编码为两个互斥的完整 JSON 对象格式。替换必须有正文和合法引用；省略的正文、引用和自测字段必须为空，缺口说明必须非空。程序校验仍保留，模型不能一边选择省略、一边保留未核实的文字。输出约束的变化进入配方指纹，旧失败尝试与预算不重置。

真实长文试点选择同一保留工程的 4 份完整原生源码，共 8,190 字符；固定 4 处完整语句摘录，分别为 97、154、252、270 字符。另两份较长源码本次未纳入，范围说明明确保留此缺口。实际生成、来源对照及网页结果另记于目标执行记录。

## 从原文反查遗漏

修订命令新增显式 `--source-scoped-additions`：没有对应解释的遗漏按章和来源拆成新增段落，同一来源的多个范围仍一起处理。每次补写读取这一份完整冻结原文，引用枚举仅包含该来源，最多一条；已有章节只用于避免重复，不能成为事实依据。资料不足仍须省略并记录缺口。默认策略、已有文章与历史配方保持兼容。

新策略使用独立配方及三次预算，但没有改变的段落、自测等修订继续使用原任务的请求指纹、断点和次数限制，不能通过切换策略重置失败预算。真实补写旧任务三次漏引来源后停止；新策略逐项核对并复用 11 个原断点，仅新增 4 次逐来源生成，完成 15 项修订并保留全部原文和原样代码。相关 32 项回归已通过，包含旧失败记录逐字不变、同源范围合并、不同来源分段、断点复用和未改变目标的预算不可重置。新稿仍须独立检查，结构通过不代表语义合格。

修订入口可重复指定 `--omission-job`，绑定最多 4 份完整历史报告的指纹；来源核对和遗漏发现共同形成稳定修订目标。部分覆盖优先修订同章对应段落，只有代码或没有对应解释时补写同章正文；原样代码保持不变。补写在原段落删除后应用，避免位置漂移，发布前重新验证全部绑定报告。`--prepare-only` 仅冻结完整请求、来源与 schema，不读取实时权重或调用模型，不发布文章；内容指纹相同的准备记录复用，已有记录被篡改则拒绝覆盖。

`course_wiki_completeness` 单独检查原文是否讲进文章。每章使用完整的固定原文，连续分配每个字符到不超过 240 字符的范围；相邻范围结合上下文阅读，不把边界当成句子或源码块边界。单章原文仍限制 3,200 字符，每次完整上下文最多 16,000 字符。不以模型摘要代替原文，不把原始出处面板、资料缺口或未经解释的代码展示当作已经讲清知识。

每个范围必须且只能返回一次判断：已讲到、部分讲到、遗漏、模型认为无需展开或无法判断。已讲到和部分讲到必须指向同源文章中的具体解释或自测；仅有代码引用不能算已讲清。未进入分章检查的固定来源另列为未检查，不用已检查的来源代替它们。字符分配完整只说明输入没有静默丢失，不说明所有知识已讲清。

遗漏检查有独立的锁、任务目录 `wiki/completeness-jobs`、三次跨重启失败预算、阶段断点及每篇状态。只在模型调用时使用既有共享 GPU 锁，不修改生产提取代码、文章正文或原有写作状态。完成报告保存在任务内，切模型后仍可按原 job 读取历史；读取时重新核对文章指纹、配方、范围、请求、阶段结果、汇总和未验收标记。

本机接口 `/wiki/api/completeness/<article>?job=<optional-history-job>` 返回完整报告或真实的未开始／进行中／失败状态。网页按章折叠显示每个判断、理由、程序还原的原文和文章位置，包含模型认为无需展开的范围，以便核查遗漏风险。失败不发布部分结果。无论模型是否报出遗漏，语义、完整主题覆盖、图文、代码运行与原视频删除资格均保持未验收，不输出“完整率”或“准确率”。

## 已发布 Wiki 的独立快照

`course_wiki_snapshot` 提供 `create`、`verify --smoke`、`restore` 和 `serve`。快照固定已发布文章的全部保留版本、来源笔记、术语索引、原样代码、引用图片，以及与文章关联的完整来源对照和遗漏检查历史。逐文件清单绑定长度与 SHA-256，原图还核对真实图像格式；检查必要依赖是否全部进入清单。创建期间发布指针或文件发生变化则拒绝完成，不覆盖已有快照。恢复拒绝非空目录和与备份重叠的路径，复制后再次校验，默认保留 32 GiB 空间。

阅读器的 Python 包源码与网页资源随快照保留，`PublishedStore` 不需要提取 SQLite。首页和文章明确提示快照范围，实时全量进度接口提示不包含该数据；文章、搜索、出处、自测和引用图片继续使用实际阅读路由。`reader-requirements.txt` 记录当前读取与路由检查所需依赖版本，README 提供独立启动方法。

快照只覆盖创建时已发布内容，不包含全部课程音视频、全部附件、模型、Python 环境或浏览器学习记录，也不构成全课程备份、语义验收或原视频删除依据。未打包离线安装依赖，因此不能称为新电脑无需准备即可启动。全归档备份与环境恢复仍需另行完成。

快照收集和校验还会检查修订稿的父稿指纹，以及显式绑定的前向历史报告和遗漏报告。即使人为从文件清单中同时移除了丢失报告，也不能因此把缺少修订依据的快照验收通过。配对报告修订的独立恢复回归验证了完整报告可离开原目录读取；删除报告并同步修改清单后，验证仍必须失败。当前已发布 11 个版本的依赖核对通过，这不表示本轮已经重建全部备份。

恢复验证脚本 `tests/wiki_snapshot_isolated_reader.py` 使用独立 Python 进程，优先从恢复目录加载代码，禁止打开原始归档、项目源码和 SQLite，核对实际导入的本项目模块全部来自恢复目录，并通过实际阅读、搜索、原图和来源笔记路由验证。该方法无需改名或移动正在生产的归档，也不会暂停现有提取任务。

## 固定完整学习任务的自测生成

`course_wiki_synthesis --fixed-assessments` 将计划中每道题的完整 `focus` 固定为可作答的学习任务；生成前拒绝重复目标。模型的输出 schema 不含题干，只能生成答案、解释、判断标准、出处、易错点和资料缺口；模型自行提供题干时拒绝结果。此策略仍需逐题检查原文支持，不能用程序题干冒充答案质量或语义验收。

新策略使用独立配方指纹，绑定原正文任务 ID。概述和各章仍通过原任务的完整请求与内容指纹校验读取，保留原模型预算；四道题使用新 schema 重新生成。旧题目的全部响应与失败次数保留，切回默认策略不能获得额外尝试。默认生成策略和历史配方不变。

## Windows 离线阅读运行包

`python -m wechat_decrypt_tool.course_wiki_runtime create --destination <新目录>` 从本机安装环境复制 CPython 和阅读依赖的固定版本闭包，不联网，不复制转写和生成模型环境。运行包和已发布 Wiki 快照分别保留。包内 `run-wiki.ps1 -Snapshot <完整快照目录> -Port 3004` 使用包内 Python，以 `-I -B` 启动快照代码；启动前校验运行文件与快照清单。

运行包的 `verify --root <运行包>` 和 `restore --root <运行包> --destination <新目录>` 检查逐文件大小与 SHA-256、路径边界、Windows 大小写重复别名和空间余量。恢复目标必须全新且与源目录独立。文件校验不等于执行验收；真实独立运行须另存收据，核实 Python、依赖、项目模块来源、实际阅读／检索／图片接口，以及对原安装和原资料路径的访问尝试。

该运行包仅支持 Windows x64，仍依赖 Windows 系统组件。它不包括课程数据、GPU／渲染工具或浏览器学习记录，不证明全部课程已归档或允许删除原视频。之前快照附带的依赖版本清单仍保留；仅有清单不表示具备这一离线运行包。

## 扩展未尝试课程的有限批次

`python -m wechat_decrypt_tool.course_wiki_batch --root <归档目录> prepare --limit 4` 只在 CPU 上建立第一轮主题队列，不调用生成模型。选择已发布笔记，排除所有已有文章引用、历史选题尝试及其他批次预留的课程；即使前次选题失败也不会因新批次而获得新预算。批次清单绑定课程 ID、完整笔记指纹、固定模型权重和固定学习任务策略。

以返回的批次 ID 运行 `python -m wechat_decrypt_tool.course_wiki_batch --root <归档目录> guard --batch <批次ID>`，使用现有 Wiki 温度守护角色，保持 200W 上限、70°C 暂停和全局 GPU 互斥。另一健康守护任务仍在运行时不能重叠启动。每节课只选题一次，再生成有边界草稿、逐主张来源核对及逐来源遗漏核对。未选中的片段原样记录，不能把每课一个主题视作完整课程覆盖。

进度在 `wiki/theme-batches/<批次ID>/progress.json`。GPU 等待返回可续跑状态；暂停保留断点并结束，不自行清除暂停。普通失败转 `needs_review`，继续本批其他课程，随后续跑跳过失败项，不调用自动修订。生成及核对仍沿用各自原有跨重启预算。已完成行须通过实际文章与两份完整报告的读取器重新验证，再与完成时指纹比较；丢失或变化转待检查，不用状态行冒充已完成或自动重做。`finite_batch_finished` 只表示有限队列已走完，具体失败与模型发现的问题仍在各行及绑定报告中，语义与完整主题验收均保持未完成。

## 完整目录的分批选题

`course_wiki_directory` 将一节课的全部来源目录固定到 `wiki/theme-directories/<目录ID>/manifest.json`。原始笔记完整指纹、每个窗口的原样标题与摘要、可冻结／不可冻结状态及页面顺序均保留。每页最多 16 条、完整目录条目的 JSON 最多 8,000 字符；一个条目本身过大时明确拒绝，不截短文字。读取时重新验证原始笔记、原样目录及分配结果，任何遗漏、重复或源版本变化都会拒绝。

`course_wiki_batch --root <归档目录> prepare-directories --video <课程ID> --video <另一课程ID>` 固定所有页面到一个有限批次。运行仍使用 `guard --batch <批次ID>`。分页选题只向模型提供本页完整目录和同课已有主题，避免全库标题不断挤占上下文；模型必须从本页允许的原文窗口选题，本页无法构成连贯四章主题时应明确跳过。目录页边界不是知识边界，分页成功也不证明文章已覆盖该页全部知识。

默认单目录策略及其历史配方不变。分页策略分别绑定目录 ID、页号、源笔记和模型权重；每页的原尝试预算跨重启保留。相同准备请求返回原批次，重组或扩充另一个批次不能重复预留相同页面。每页保留全课未选中窗口，以及本页的完整窗口清单；没有进入文章或未通过单次原文容量门禁的来源仍明确未完成，不能因为目录元数据已经分页就视作原文均已处理。

## 原图、图注与正文的本地视觉核对

`python -m wechat_decrypt_tool.course_wiki_visual_review --root <归档目录> --article <文章ID> --wait-gpu-seconds 3600` 是独立的原图核对器。必须置于已有的 200W／70°C 守护流程下执行，共用 GPU 锁；不能直接重叠启动另一个 Wiki 守护角色。它读取文章实际选用的保留原图、完整章节正文、原样代码及图注，并把 OCR 描述明确作为未经证实的机器文字。只向本机安装权重发送原图字节，不使用外部服务；无正文图片时不加载模型。

单次完整上下文超过 6,000 字符则明确拒绝，不截短章节。视觉调用固定为 16K 上下文和 1,800 个输出 token 上限，保留实际输入 token、模型显存和上下文记录；运行中的本机模型须匹配固定权重、实际使用 GPU，且上下文余量可核对。图片保持原保留字节和 SHA-256，不把能解码当成图文对应。

每处图片分别返回相关性、图注支持、实际可见观察、缺失信息和限制。观察区域以原图 0–1000 的坐标表达，格式及边界由程序校验，观察内容与框本身仍是未独立复核的模型判断。支持性结论至少有一个可见观察。文章、原图、模型、完整请求和 schema 绑定到 `wiki/visual-review-jobs/<任务ID>`；三次失败预算跨重启保留，GPU 等待与暂停不消耗模型失败次数。读取完整报告时重新验证绑定及逐图结果，禁止把接受标志改为通过。

新的已发布 Wiki 快照会一并保留完整视觉报告、请求、阶段结果和尝试历史，并在独立恢复时重新校验。旧快照没有这些新报告；文件保留和模型观察均不等于独立语义验收、全课程视觉完整性或原视频删除资格。

阅读页“原图核对”通过只读 `/wiki/api/visual/<文章ID>` 获取全部匹配历史；可用 `job` 查询特定任务，读取不会调用模型。完整报告逐一重新验证文章、原图和记录；损坏的一项标为不可采用，不隐藏其他历史或阻断正文。未完成进度只有在 PID 与创建时间仍匹配时才显示正在执行，否则显示未完成。界面分别展示原图、章节位置、图注与相关性判断、可见文字和坐标、可能遗漏信息及限制；区域始终标为未经独立复核的模型观察。没有报告及正文无配图分别明确说明，不以空报告表示通过。独立快照 smoke 检查也核对该接口与完整本机报告一致。

## 超容量窗口的完整原文分配

`course_wiki_evidence.create(store, video, section)` 固定一整个窗口的全部语音原文及时间范围内的截图文字和原图哈希，写入 `wiki/evidence-partitions/<ID>/manifest.json`。连续范围优先在线尾或句末分界，每段最多 2,000 字符；不删除空白、不改换行、不总结、不补写代码，边界明确不代表语义或代码块完整。按原顺序分配所有范围，每页仍遵守原有 3,200 字符及 11,500 字符 JSON 门禁，单条元数据本身超限时明确拒绝。

写作选择保持原有课程及父窗口，并显式增加 `evidence_partition` 和整数 `evidence_page`；每次只读取该页完整分配范围。每段来源携带完整原文指纹、字符长度、起止范围及原引用 ID，唯一引用键包含范围。清单重新推导时必须与完整冻结原文、固定分界算法及每页分配完全一致，自洽重算清单哈希也不能掩盖漏字、重叠或改文。未选择的页仍保留，不算已经写入文章。

`prepare_plan` 合并各章与概述实际使用的页；`DraftJob` 将范围限制提示绑定到配方及实际模型请求，旧的整窗口配方和失败预算不改变。发布和读取重新验证页绑定及每段原文，原图字节保持。新计划必须对应当前来源笔记；已发布文章则读取当时冻结的来源对象，允许当前笔记继续更新。快照保留该完整旧对象、所有关联原图及范围清单，并在独立恢复时重新验证，缺失时拒绝验收。字符分配完整不表示知识讲解完整、代码可运行或语义合格。

## 复用写作断点的快照依赖

`course_wiki_snapshot.writer_dependencies` 从已发布文章的固定写作配方递归收集 `unchanged_body_job` 和 `unchanged_claim_job`，即使依赖任务本身未发布，也保留其清单、阶段结果和全部尝试 JSON。核对任务 ID 与完整配方哈希、原文包、模型指纹和流水线一致性，并核对阶段数据哈希及输入指纹格式；拒绝越界身份、循环依赖、缺失或变化的清单。它不调用模型、不重置失败预算、不修改原任务。

固定题目策略须保留完整概述与各章原正文断点；逐来源补写策略依据冻结的来源核对与遗漏报告重新列出必需的旧修订阶段。依赖目录或必需阶段缺失时，创建及验收均拒绝，即使文件清单同步删掉该项也不能把缺失隐藏为成功。恢复阅读仍只依赖快照本身；这些字节与依赖校验不等于重新生成、语义正确或完整课程覆盖。
