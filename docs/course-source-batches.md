# 有限课程来源接续与发布

完整范围始终保留 340 节有声课程、2 份无声来源和全部可恢复课件。此控制器只安排最多三节新来源的
原材料处理，来源导出与来源笔记发布均不能计作完整文章或语义验收。

`course_source_batch prepare` 绑定当前正在运行的单节 `course_knowledge` guard/worker 的 PID、
完整创建时间、课程清单、原生产代码、本地模型文件状态及三个来源的身份。进程身份应直接从已核对的
状态和 psutil 读取，保留创建时间的完整精度。模型、原 ASR/OCR/来源笔记代码及已验证 GPU 配方均不变。

选择范围只包括数据库尚无登记的来源；已存在转写、画面或其他处理输出的目录不参与选择。
只有 `audio.json` 和 `audio.m4a` 的目录可以作为已验证的音频归档输入保留：核对原视频身份、音频清单、
音频大小与当前文件状态，保存清单和文件的原摘要。预处理过音频不等于已完成或尝试过转写。
原生产音频读取与 ASR 校验继续保留，准备过程不复制或重新生成这些音频。
实际 `transcription_audio` 在没有替代恢复绑定时仍返回原视频路径；本控制器不会改为从归档 `audio.m4a`
读取。这里复用的是已有音频归档成果及其身份记录，不是更换生产 ASR 的输入选择策略。

准备结果保存在 `output/course-knowledge/wiki/source-batches/<批次 ID>/plan.json`。
`course_source_batch worker --batch <批次 ID> --reader-url http://127.0.0.1:3003` 观察准确的原进程，
在原 guard 与 worker 均退出后核对成功终态及导出，再依次运行选定来源。
每节使用相同共享 GPU 锁、200W 保护上限、70°C 暂停和 C/D 各至少 32 GiB 预留。
`supervisor-stop.flag` 和 `pause.flag` 均会停止接续；守护不会自动解除温控暂停。

每节成功后校验数据库与导出文件，使用现有发布器更新完整来源目录，逐项验证 HTTP、关键词目标与图片，
保存单节结果、原 guard/worker/run-plan 状态及独立导出备份，再开始下一节。阅读器 3005 仍只展示
已经完成相应文章审核链的正文；内部来源归档服务位于 3003。

控制器的 `started.json`、失败收据和已完成单节结果均须保留。同一控制器不会因重启获得新尝试额度。
失败时先核对所指来源和原 ASR/OCR/来源笔记缓存，按保存的原单节命令恢复现有生产断点；温控暂停必须
有之后明确的用户恢复指令。原单节验收后，才能为尚未尝试的尾部重新准备有限计划。不得删除启动记录、
重置原模型次数或把未完成来源跳过后宣称整批成功。

批次输入、源码、模型状态摘要和运行凭证都有独立备份；当前这些核验不代表完整模型环境或全部归档恢复完成。
运行期间不得改变计划绑定的源码或输入，修改代码前应先核实它没有被健康任务使用。
