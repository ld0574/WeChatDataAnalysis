# 课程 Wiki：完整图文文章交付标准

2026-11-03，用户删除旧 Goal 后要求重新创建。本规范承接最新要求，优先于历史计划中将时间分段、来源笔记、逐段摘要或原始画面作为阅读主体的设计。系统 Goal 必须真实处于运行中；不能用本地文档代替系统状态。

## 目标与范围

将课程资料整理成可以独立阅读、检索、复习的本地 Wiki，使知识库成为学习入口。范围保留全部 340 节可恢复音频课程、2 份无声来源以及所有可恢复课件。第一节是完整课程样板，不是缩减后的最终交付范围。

## 读者得到什么

- 每节课有一篇连贯、可独立阅读的图文文章，以知识结构、前置概念、问题和学习逻辑组织；跨时间窗口合并同一知识点，消除重复讲解。
- 正文充分解释课程实际涉及的定义、原理、步骤、例子、适用条件及误区；按实际材料选择结构，不套固定章数，也不把来源摘要拼起来充当成品。
- 图示用于解释概念、关系、流程或比较，必须与正文和材料一致。读者无需查看原始画面才能理解文章。
- 自测包含答案、解释和掌握标准，检验理解与应用能力，避免只考术语复述。
- 保留课程目录、全文检索、跨课关联和学习记录。未完成课程标为“整理中”，不能用原始来源笔记冒充已完成文章。

## 内部证据与阅读版分离

原视频、转写、OCR、原始截图、引用、时间定位和哈希映射全部保留在内部，供核对、恢复和覆盖审查使用。面向读者的正文和阅读版导出不展示原始画面、逐字稿、OCR 面板或老师的时间窗口列表。内部归档及管理检索与阅读版使用明确区分的数据契约，不能仅靠折叠或 CSS 隐藏原文。

课程材料及模型处理保持本地。工具输出只报告状态、数量、标识、哈希和路径，不打印课程正文、原始识别材料、聊天内容或密钥。

## 逐课质量验收

1. 固定全部可用原始材料清单、版本和哈希；长证据允许无损拆分，不得静默截断，也不能仅用已有摘要替代原文。
2. 建立“原始证据 → 有效教学知识点 → 正文章节、图示和自测”的内部账本。覆盖审查检查遗漏、重复和证据支持，排除口头填充内容须留理由。
3. 按知识依赖重新规划文章结构，并写出连贯讲解；分别检查事实支持、例子、图文一致性、阅读完整性和自测质量。
4. 对未恢复、部分支持和待复核项如实记录。数量齐全、自动生成完毕、结构测试通过均不等于语义质量验收通过。
5. 验证实际阅读路由、检索、图示、自测、学习记录及阅读版隐私隔离。首课样板达到上述要求后，再推广到全量。

## 运行、保护与交付约束

- 沿用本机 GPU 与已验证模型，遵守共享 GPU 锁；功耗不超过 200W，达到 70°C 即暂停，不自动进行温控恢复。C、D 盘各保留至少 32 GiB 可用空间。
- 保护健康的抽取、发布、备份和 PDF 队列进程及其绑定代码、计划与输入；不为观察超时或进度暂时不变而重启任务。
- 保留全部断点、失败、跳过、预算、暂停标记、已有备份和 `supervisor-stop.flag`；不重复执行已验收批次，也不清空预算来循环重试。
- 不重复询问 `14-vision.pptx` 的未知密码，保留该例外。未恢复材料不得计作已完成。
- 用户验收前不得删除原始视频。交付包括可移植备份、独立恢复验证、真实进度和剩余例外；代码与文档提交并推送到 `dale`，私有课程材料不得提交到 Git。
- 仅在全部范围和验收要求实际完成后，才将 Goal 标记完成。后续进度汇报必须区分原始材料恢复、来源笔记、课程成品、语义验收与备份恢复状态。

主课程 GPU 任务可用 `python -m wechat_decrypt_tool.course_archive_gpu --root <归档根目录> --asr-model <本地 Qwen ASR 目录>` 沿既有断点恢复。该入口复用原转写、OCR 和来源笔记缓存，保留批次大小 4 与 float32，不改动已绑定的生产模块。GPU 守护在检查温度和 200W 上限的同时，每次采样核对归档盘、系统盘各至少 32 GiB；任一盘低于预留量时保存具体磁盘检查记录并暂停，不自动恢复。现有 `pause.flag` 会阻止启动，`supervisor-stop.flag` 不会被清除；启动前仍须核实旧 worker 和 guard 均已退出并备份旧状态。

已暂停的有限 PDF 批次不能重新作为“未尝试”批次启动。`course_pdf_queue_resume prepare --prefix <原批次> --backup <独立输入备份目录>` 会核对原绑定、原 worker 已退出、暂停计数和既有数据库历史，独立重渲染并验证已提交页，核对未提交但已缓存页面的原始像素，并备份该范围的数据库行、原图、缓存、裁图及局部推理记录。准备状态只证明部分断点可续跑，不代表全批或整份课件完成。随后以同模块的 `guard --prefix <原批次>` 运行，沿原计划和模型复用已提交页及缓存；新进度单独保存，原失败和进度不覆盖。完整批次必须再次通过原独立校验和结果备份，确认原有页历史未改变，才能生成该批次的终态凭证。终态失败禁止自动重试，后续批次仍须核对前驱结果后顺序调度。

## 下一执行顺序

先固定第一节完整材料并建立覆盖账本；实现按知识组织的全文写作与解释图、自测；改造默认课程阅读页；完成首课实际阅读和隐私检查；再用相同契约逐课推广。已有独立恢复工作继续按原断点与绑定批次推进，不以新 Goal 为理由重跑或改写旧任务。

首个实现阶段使用 `course_textbook_evidence` 固定全节证据及候选配套笔记本的完整单元格和文本输出，以哈希和字符范围证明无损分配；调度分页不作为文章章节。`course_textbook_ledger` 逐页提取教学知识并单独检查事实支持、遗漏与非教学排除，每页至多一次语义修复，每个模型阶段最多两次结构尝试。执行配方、模型版本、依赖代码与预算绑定到证据清单，重启不能静默刷新预算。此阶段仅产生内部写作账本，不发布来源片段，也不宣称成品文章或全课语义验收已完成。候选课件关联及图片证据仍须另行核对。

模型若仅漏列来源的去向，`course_textbook_ledger_cache` 可检查原来两次完整且未截断的响应：只允许借用另一份响应中已明确给出的非教学排除理由，且该来源不能在任一响应中被列为教学依据。不得自行填默认排除、合并新事实或刷新尝试预算。恢复前必须确认原 worker 已退出并取得同一清单的排他锁，恢复记录绑定原始失败文件、输入、数据与恢复代码哈希；原失败和预算保留，随后仍须执行全页原文复核。这是零模型调用的机械恢复，不是全课质量通过。

原先自由列举来源的协议在第四个调度页出现遗漏及相互冲突的分类后，使用 `course_textbook_keyed_ledger` 的有版本后继协议。每份目标原文是 schema 的必填键，结果严格二选一：包含教学知识点，或给出非教学理由；引用由程序绑定到该来源。审核也固定每个知识点和排除项的键。后继清单核对旧模型响应、输入、缓存恢复链及 GPU 上下文指标，零模型调用复用已通过的页面；对最后一份无冲突的失败候选，仅为缺失来源新建有限提取，随后审核全页。尚未开始的来源分组使用新协议，原失败预算保留，后继配方也有不可静默刷新的独立绑定。

## 完整文章写作与阅读契约

`course_textbook_authoring` 接受已经完成、哈希一致且没有未解决语义问题的完整账本。先分层组织全部知识点，再形成整节课的概念结构；每层对每个输入强制分配组及学习次序，检查缺项、重复、环和孤立节点。下层调度批次不固定为正文章节。所有知识点依次分配给写作任务，不截断原文或超大单点；不能完整容纳的上下文会明确停下。

中间账本仍有争议时，可以使用独立的 `course_textbook_composition` 先写完整的内部工作文章，正式写作入口的严格检查保持不变。此入口只接受已经终结的来源修订任务：隔离争议来源对应的旧提取断言，完整保留其他已审核知识点，将每份争议原文作为明确待核对的写作任务，并附前后相邻完整原文以理解指代。原账本、负面意见、提取与修订预算保持原样，不重新执行来源修订；新的文章阶段有独立且固定的写作、审查和每节至多一次修复预算，启动合同不允许通过改模型、配方或重复启动刷新。

工作文章必须覆盖所有保留的知识点和待核对原文。模型须明确区分真实教学与行政、导航等非教学材料；教学任务必须指向有目标原文引用的正文段落，非教学排除必须留独立可复核的理由。正文与章节按知识关系重组，不按这些内部任务编号排列。此入口始终保留“完整原文到工作文章覆盖复核仍待完成”的质量问题，即使小节审核全部通过也只保存内部文章，不生成 `reading.json`、`reading.html` 或发布凭证。后续仍须逐原文检查实际文章的遗漏、条件、例子和限制，并解决继承的争议，才能按原标准交付阅读版。不能用新工作文章假称旧账本已通过，不能将内部文稿直接接到读者路由。

2026-11-03 的一次有限合成对照试验共 8 项，仅 5 项符合预期；加入相邻上下文后仍存在漏检明确输入条件的情况。该结果不能证明审核模型可靠，也不能用来取消争议或放宽发布检查。它说明单一“通过/需修改”的模型结论不足以证明原文知识覆盖，后续完整覆盖检查须直接核对原文的具体教学要求及文章对应段落。

`course_textbook_source_coverage` 为这项后续复核建立逐原文的无损字符范围计划，保留标点、空白、代码及全部文本，逐项绑定哈希并验证可完整重建。划分单元仅用于强制逐项核对，不代表已经提取或验收的知识。审核 schema 要求每个单元分别判断是否包含教学、文章是否完整涵盖以及实际对应段落；没有正文也可以如实记录教学遗漏。已覆盖的示例不能替代另一单元中未覆盖的输入条件，没有实际段落映射不得宣称覆盖。当前计划和结构验证本身不构成语义质量或发布凭证。

概念规划若仅因组内序号并列而耗尽两次结构尝试，`course_textbook_plan_cache` 可在确认原工作进程退出后做零模型恢复。它重建原规划分区，核对两个完整响应、原请求、输入、GPU 指标、配方及预算，只允许保留最早完整候选的全部分组、标题、目的和条目归属；并列项按原输入键顺序消解，原本严格有序的关系不变。空组、遗漏输入、重复标题、越界分组、截断或其他错误不得按此恢复。原失败文件保留，恢复回执列出编号变化及哈希；后续仍须执行全部写作和审查，不据此认定内容已通过或允许发布。

账本仅导航。每个写作与事实复核请求都带上当前任务全部知识点的完整原始依据，同时保留按段落核对的内部覆盖映射。写作输出包括连贯解释、有依据的原创结构图、回答与解析齐全的自测；独立复核逐项检查段落、知识覆盖、图示、自测和可读性。每个模型阶段最多两次结构尝试，每个小节最多一轮语义修复，预算及失败跨重启保留。完整阅读块有小节重叠，保证每个小节和相邻衔接都接受检查，不能只审标题或摘要。

`course_textbook_article` 使用逐字段白名单投影生成阅读 JSON 与无外部依赖的 HTML/SVG。原始材料、截图、引用、内部覆盖映射和附件待核对记录不能经此契约进入阅读版。只有本地自动检查没有剩余问题才生成阅读草稿文件；其状态仍是待实际阅读复核，不能据此标记人工验收、完整课件覆盖、语义准确或视频可删。首次部署前还须核对候选课件关联与图片证据、接入阅读路由并完成实际阅读及隐私检查。

运行方式为 `python -m wechat_decrypt_tool.course_textbook_authoring --root <归档根目录> guard --inventory <完整证据清单哈希> --ledger-job <已完成后继账本任务 ID>`，沿用共享 GPU 锁、200W 功耗上限与 70°C 暂停阈值，不自动热恢复。当前账本仍在运行时不得提前启动文章任务，也不得为后续启动清除现有暂停、停止或预算标记。

完整账本仍有争议时，`course_textbook_resolution` 只处理负面审查涉及的来源，并对共享引用做闭包，防止替换跨来源知识时遗失邻接依据。每次模型请求只重新判断一份完整原文；教学知识必须提供可机械验证的逐字引文，再做一次独立事实与遗漏复核。原有正确来源、旧判断、失败及预算都保留。这个后继绑定完整父账本、精确争议范围、原文、模型与代码，不能重启刷新结构尝试；每个阶段最多两次结构尝试，没有额外语义修复循环。未解决的审查仍进入新账本的问题清单，不允许冒充可写作或已验收状态。

如果仅因引文空白与原文不一致而耗尽两次结构尝试，`course_textbook_resolution_cache` 可以在原 worker 确认退出后做零模型恢复：两次原响应须在删除空白后得到相同的候选，每处修复必须唯一定位到完整原文的连续字符范围，不得改动任何非空白字符、事实、教学判断或排除理由。恢复记录绑定原失败文件、来源、字符范围、输入、模型指标与恢复代码，原失败及预算保留，随后仍须执行独立来源审核。标点差异、实词改写、不唯一匹配或其他结构错误均不得按此恢复。

模型改写了引文时，不能伪称完成上述空白恢复。对于不超过 2048 字符的完整短来源，可显式使用另一个有版本的“完整原文依据绑定”操作：确认两次失败均仅由非逐字引文导致，固定选取最早一次原候选，保留其全部知识点字段，只将引文指向完整原文。不得合并候选、修改事实、另行生成知识或重新分配提取预算；回执记录所有原候选和失败的哈希、固定选择规则、完整原文范围及代码版本，不宣称原模型引文是逐字引用或候选已得到事实支持。随后必须沿用原阶段预算进行独立事实、条件和遗漏审核，负面结论原样进入问题清单，仍然阻止文章写作。该操作只解决引文定位，不能用来消除语义问题或宣称验收通过。

上述完整来源复核结束后，`course_textbook_source_revision` 可对仍有负面意见的来源做一次有限语义修订。启动前重新核对原父账本、完整执行范围、每份原候选及负面审核缓存的输入绑定、哈希和编译映射；正确来源保持原样。修订请求包含该份完整原文、原候选与原审核意见，不能将审核意见当作事实。程序绑定完整原文引用，再执行独立支持与遗漏审核。每份来源仅有一轮修订、每阶段两次结构尝试，父任务保存唯一后继绑定；改配方或递归修订已修订账本都会被拒绝，不能借此增加原任务预算。剩余负面意见继续阻止文章写作，旧失败、预算及账本完整保留。

如果同一来源审核的两次结构尝试均因“通过结论同时列有缺失项”而失败，`course_textbook_audit_cache` 只能做保守降级：确认旧 worker 退出，核对原任务、来源、候选、模型指标及两次失败的完整输入绑定，保留最早完整意见的全部理由和缺失项，只把 `supported` 改为 `needs_changes`。保存原失败、数据与代码哈希，不调用模型、不刷新预算、不移除任何缺失项。降级后继续同一有限任务的剩余来源，负面意见仍进入问题清单并阻止文章写作；这不能作为事实正确或质量通过的凭证。

`course_textbook_reader` 提供独立的阅读与正文检索接口。进入阅读对象库前必须核对文章完成状态、质量问题清单、完整账本、覆盖映射及白名单投影；阅读对象按内容哈希保存，版本更替保留历史。目录只展示课程名称、集合及整理状态，不回退到来源笔记；全文检索、HTML 阅读和导出只读取公开阅读契约。草稿仍明确标为待复核，阅读服务默认仅绑定本机，不代表已部署或完成实际阅读验收。
