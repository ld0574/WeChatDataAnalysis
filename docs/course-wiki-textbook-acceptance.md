# 课程 Wiki：完整图文文章交付标准

2026-11-03，用户删除旧 Goal 后要求重新创建。本规范承接最新要求，优先于历史计划中将时间分段、来源笔记、逐段摘要或原始画面作为阅读主体的设计。系统 Goal 必须真实处于运行中；不能用本地文档代替系统状态。

## 目标与范围

将课程资料整理成可以独立阅读、检索、复习的本地 Wiki，使知识库成为学习入口。范围保留全部 340 节可恢复音频课程、2 份无声来源以及所有可恢复课件。第一节是完整课程样板，不是缩减后的最终交付范围。

## 读者得到什么

- 每节课有一篇连贯、可独立阅读的图文文章，以知识结构、前置概念、问题和学习逻辑组织；跨时间窗口合并同一知识点，消除重复讲解。
- 正文充分解释课程实际涉及的定义、原理、步骤、例子、适用条件及误区；按实际材料选择结构，不套固定章数，也不把来源摘要拼起来充当成品。
- 图示用于解释概念、关系、流程或比较，必须与正文和材料一致。读者无需查看原始画面才能理解文章。
- 自测包含答案、解释和掌握标准，检验理解与应用能力，避免只考术语复述。
- 保留课程目录、全文检索、跨课关联和学习记录。未完成课程标为“整理中”，不能用原始来源笔记冒充已完成文章。

## 内部证据与阅读版分离

原视频、转写、OCR、原始截图、引用、时间定位和哈希映射全部保留在内部，供核对、恢复和覆盖审查使用。面向读者的正文和阅读版导出不展示原始画面、逐字稿、OCR 面板或老师的时间窗口列表。内部归档及管理检索与阅读版使用明确区分的数据契约，不能仅靠折叠或 CSS 隐藏原文。

课程材料及模型处理保持本地。工具输出只报告状态、数量、标识、哈希和路径，不打印课程正文、原始识别材料、聊天内容或密钥。

## 逐课质量验收

1. 固定全部可用原始材料清单、版本和哈希；长证据允许无损拆分，不得静默截断，也不能仅用已有摘要替代原文。
2. 建立“原始证据 → 有效教学知识点 → 正文章节、图示和自测”的内部账本。覆盖审查检查遗漏、重复和证据支持，排除口头填充内容须留理由。
3. 按知识依赖重新规划文章结构，并写出连贯讲解；分别检查事实支持、例子、图文一致性、阅读完整性和自测质量。
4. 对未恢复、部分支持和待复核项如实记录。数量齐全、自动生成完毕、结构测试通过均不等于语义质量验收通过。
5. 验证实际阅读路由、检索、图示、自测、学习记录及阅读版隐私隔离。首课样板达到上述要求后，再推广到全量。

## 运行、保护与交付约束

- 沿用本机 GPU 与已验证模型，遵守共享 GPU 锁；功耗不超过 200W，达到 70°C 即暂停，不自动进行温控恢复。C、D 盘各保留至少 32 GiB 可用空间。
- 保护健康的抽取、发布、备份和 PDF 队列进程及其绑定代码、计划与输入；不为观察超时或进度暂时不变而重启任务。
- 保留全部断点、失败、跳过、预算、暂停标记、已有备份和 `supervisor-stop.flag`；不重复执行已验收批次，也不清空预算来循环重试。
- 不重复询问 `14-vision.pptx` 的未知密码，保留该例外。未恢复材料不得计作已完成。
- 用户验收前不得删除原始视频。交付包括可移植备份、独立恢复验证、真实进度和剩余例外；代码与文档提交并推送到 `dale`，私有课程材料不得提交到 Git。
- 仅在全部范围和验收要求实际完成后，才将 Goal 标记完成。后续进度汇报必须区分原始材料恢复、来源笔记、课程成品、语义验收与备份恢复状态。

先固定第一节完整材料并建立覆盖账本；实现按知识组织的全文写作与解释图、自测；改造默认课程阅读页；完成首课实际阅读和隐私检查；再用相同契约逐课推广。已有独立恢复工作继续按原断点与绑定批次推进，不以新 Goal 为理由重跑或改写旧任务。

首个实现阶段使用 `course_textbook_evidence` 固定全节证据及候选配套笔记本的完整单元格和文本输出，以哈希和字符范围证明无损分配；调度分页不作为文章章节。`course_textbook_ledger` 逐页提取教学知识并单独检查事实支持、遗漏与非教学排除，每页至多一次语义修复，每个模型阶段最多两次结构尝试。执行配方、模型版本、依赖代码与预算绑定到证据清单，重启不能静默刷新预算。此阶段仅产生内部写作账本，不发布来源片段，也不宣称成品文章或全课语义验收已完成。候选课件关联及图片证据仍须另行核对。
