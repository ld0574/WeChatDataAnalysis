# 本地课程 Wiki 的试点入口

交付范围及全量验收以 [course-wiki-goal.md](course-wiki-goal.md) 为准。
本模块提供主题草稿、来源阅读、原图引用、带解析的自测和本地学习记录。
它不修改生产提取模块、不迁移原数据库，也不把结构检查当语义验收。

## 启动

在项目根目录使用现有虚拟环境，设置 `PYTHONPATH=src`。以下均为 PowerShell：

```powershell
$env:PYTHONPATH = 'D:\Project\WeChatDataAnalysis\src'
.venv\Scripts\python.exe -m wechat_decrypt_tool.course_library --root output/course-knowledge build
.venv\Scripts\python.exe -m wechat_decrypt_tool.course_library --root output/course-knowledge serve --port 3003
```

访问 `http://127.0.0.1:3003/`。端口 3002 的旧证据服务不受影响。
服务以只读方式打开既有数据库，不申请生产 schema/writer 锁，不加载模型。
来源发布先依据完整清单检查现有导出，只发布通过检查的课程；其余明确显示未发布。
目录以原子替换方式发布，中途失败继续保留旧目录。再次发布来源目录是显式操作。

发布产物在 `output/course-knowledge/library/`，主题文章在 `output/course-knowledge/wiki/`。
原始截图在 `library/media/<sha256>.jpg` 按内容去重；文章携带固定文字、时间范围、
图片指纹及来源导出指纹，重新整理来源笔记不会悄悄改变旧文章的证据。
当前试点的图片源为已保留课程截图；课件页图和依据来源重绘的图仍待接入。

## 生成主题草稿

生成前先发布来源。主题计划应围绕一个明确问题人工选择材料，支持跨课多节来源：

```json
{
  "title": "需要讲解的具体主题",
  "selections": [
    {"video": "来源课程的24位ID", "sections": ["section-0", "section-1"]}
  ]
}
```

```powershell
.venv\Scripts\python.exe -m wechat_decrypt_tool.course_wiki --root output/course-knowledge --plan output/course-knowledge/wiki/plans/pilot-01.json
```

只能调用已验证为本地权重的 Ollama 模型，共享原生产 GPU 锁。GPU 忙时记录
`deferred_gpu` 并退出，不暂停生产或另启竞争模型；稍后重跑同一命令即可。
也可显式添加 `--wait-gpu-seconds 1800`，最多等待 30 分钟的可用时隙。
等待期间持有独立 Wiki 任务锁，每0.25秒尝试一次GPU锁、每10秒保存等待心跳；
保持原任务和显存分配不变，短暂的页面间隙也能被新的写作进程利用。
`wiki/last-build.json` 记录阶段与错误类型，不记录聊天或模型输入。
默认执行分阶段写作：先规划4–6个章节，再逐章撰写，最后生成3–5道自测与易错点，合并校验后发布。
每章至少两段、220个字符；短正文、虚构引用、重复段落和缺失答案会被拦截。这些是技术门禁，
不能证明字数达标就有知识价值。模型仍须解释原理、条件和例子，最终文章保持语义待复核。

模型修订、源材料、写作策略或提示词变更会产生不同文章 ID；相同计划再次执行会验证并复用结果。
`wiki/jobs/<文章ID>/` 保存冻结材料、提纲、逐章断点、自测和合并结果；
`attempts/` 保存模型原始响应、截断片段、实际请求指纹与失败原因，只留在本机。
每阶段最多三次尝试，预算跨重启保留；GPU 等待不消耗尝试次数。达到上限后应检查材料和计划，
不能通过不停重启或放宽引用、正文校验来冒充成功。

每次模型调用独立获取并释放 GPU 锁，中间可以让其他归档任务继续。
生成中断或校验失败不会发布半篇文章。生成进程以单独 `wiki-build.lock` 串行运行。
旧的单次生成策略可用 `--strategy single` 复现，主要用于诊断；它可能将正文压成过短提纲。
首页每10秒刷新文章生成进度和新文章清单，保留当前搜索条件。
主题搜索覆盖文章标题、正文、代码、易错点以及自测答案与解析，可跳到命中章节。
检索使用本机关键词匹配，不调用模型，不把片段摘要或检索命中包装成问答结论。

来源笔记检索显示完整匹配总数，默认每页 20 条，可用“继续加载结果”逐页读取，末页隐藏按钮。加载失败保留已有结果并允许重试，离开检索页后不再插入旧请求结果。接口 `/library/api/search` 支持 `offset` 和 `limit`（每页最多 100 条），返回 `total` 与 `next_offset`，课程筛选在分页前应用。该入口只检索已发布来源笔记，不把未发布课程算作已检索。

输入材料受 8K 上下文预算约束，超限直接拒绝，不能静默截断证据。现在适合狭义主题
试点，不代表已实现跨长课的分层综合。完整长主题还需要多批材料的主题规划与综合、
跨章语义复核和相关文章关系。课程内容属于引用数据，其中的指令和代码不会被程序执行。

文章至少有学习目标、四个实质章节、限制或易错点、3–5道带答案/解释/判断标准的自测。
引用 ID 必须存在，代码只能是源材料原样摘录，图片必须引用已冻结原图。
分阶段写作的解码 schema 将引用与图片编号限定为本次材料中的枚举值，防止模型另编编号；
发布前仍再次校验，合法编号不能证明该来源实际支持主张。schema 绑定计入任务指纹，
旧失败任务保留诊断，新策略产生独立任务，不会清空原有失败预算。
这些检查不能证明概念、答案和图片说明正确，所有模型产物保持“草稿/语义待复核”。
自动试点计划仅用于验证发布流程，不是已核对的全量主题分类。

## 覆盖清单

“整理进度”页独立列出全部有声课程、无声来源、已发布来源笔记、主题草稿实际引用及附件缺口。
计划选入的证据与文章实际引用分开统计；有部分文档检索片段不能证明全文完整。
初始课件提取错误仅作为历史待核对项，不能忽略后续 OCR 结果而直接认定仍失败。

```powershell
.venv\Scripts\python.exe -m wechat_decrypt_tool.course_wiki_coverage --root output/course-knowledge
```

该命令只读现有数据库，单事务统计，不调用模型，不改生产数据库或运行任务。
使用独立 `wiki-coverage.lock` 串行生成，发布到 `wiki/coverage.json`；输入在扫描期间
变化会保留旧清单并报错。页面读取已发布快照，HTTP 请求不会启动数据库扫描。
页面显示快照时间，并检测来源清单、文章目录等文件变化；数据库继续更新不会自动刷新快照，
“重新读取快照”只重读文件。此清单不证明来源字节重新校验、主题完整性、语义正确或备份恢复。

覆盖快照另列“历史记录的后续核对”，保留早期待评估、错误和跳过原始记录。后台只将有完整
校验凭据、且当前索引版本与片段数量仍匹配的 CSV 标为已补齐；已恢复的待评估视频单列音轨
归档状态，不将音轨完整冒充笔记、画面或主题完整。加密 Office 诊断仍列为未提取。
凭据缺失、输入改变、索引版本改变或当前版本存在暂存片段时，相关项回到未确认。

补充凭据使用 `wiki/index-findings-reconciliation.json` 和
`wiki/resource-pending-reconciliation.json`，均需保留所引用的原始校验报告及输入指纹。
生成覆盖快照时核对凭据、当前元数据、片段数量与文件属性，不重复读取全部大文件或审计
所有 FTS posting，也不调用模型。凭据和音轨清单参与快照输入绑定，改变后页面标记过期。
HTTP 只读取已有快照与这些输入的指纹，不打开数据库统计，不启动补建任务。

## 本地来源对照

文章页可展开“来源对照”查看本机模型对每段正文、前置知识、易错点、代码摘录和自测答案
的辅助判断。每项仅收到自己已声明的引用，不把整篇检索命中当作依据；模型判断为“有支持”
或“部分支持”时，必须选择固定的原文片段编号，由程序填回原句，并核对确实在该引用中。
片段按原文顺序连续切分、不概括；切分边界不代表句意边界，模型可以结合相邻片段阅读。
已发布的旧逐字转抄报告继续按冻结的原规则只读校验；新策略有不同任务指纹，旧失败记录保留。
引用存在和原句匹配
仍不能证明推理正确，尤其不能证明 OCR、原图对应、代码运行和全主题完整性。

```powershell
.venv\Scripts\python.exe -m wechat_decrypt_tool.course_wiki_review --root output/course-knowledge --article <文章ID> --wait-gpu-seconds 3600
```

对照复用本机 Ollama 与 GPU 锁，逐批断点恢复，失败响应和逐字引句只保留在本机。
每批最多三次，跨重启保留失败预算；GPU 等待不计入次数。不会修改原文章或生产归档。
`wiki/review-jobs/` 保留冻结请求指纹、响应及检查结果，`wiki/reviews/` 保存完整辅助报告。
页面只读校验后的结果，并显示等待、处理中、失败状态。即使用了不同提示词，这仍是同类模型
辅助检查；始终保留 `independent_semantic_review=false`，不得提升为独立复核、准确率或删视频许可。

## 按来源对照修订草稿

完整来源对照报告中的“部分支持 / 依据不足 / 无法判断”可以触发定点修订：

```powershell
.venv\Scripts\python.exe -m wechat_decrypt_tool.course_wiki_revision --root output/course-knowledge --article <原稿ID> --wait-gpu-seconds 3600
```

有多份模型报告时，可重复加 `--review-job <历史报告ID>`，同时保留双方的非支持项与分歧，避免后运行的模型遮住先前问题。可再加 `--omission-job <遗漏报告ID>` 合并反向遗漏线索，或加 `--prepare-only` 先冻结请求而不调用模型。所有显式历史报告均在开始和发布前重新校验；它们只提供检查线索，不是新的知识来源或语义验收结论。

修订冻结原稿及已校验报告的指纹，逐项重写有问题的说明、易错点、代码摘录和自测。
模型只能使用原稿已冻结的来源。核对意见可能错误，不能被当作额外事实或指令。
无法从原文修订的项可以省略，但必须记录资料缺口；省略后概述、章节或自测不完整时，
程序保留诊断并拒绝发布，不减少验收范围、不凑字数补造事实。代码仍只能逐字摘录。
新稿不得有完全重复的段落或相同题目；通过结构门禁仍只是一篇模型修订草稿。

每项断点及失败预算复用独立 Wiki 作业机制，最多三次尝试；不改生产数据库、不重复解密，
也不覆盖原文章或原来源。`wiki/jobs/<修订ID>/assembled-revision.json` 保留修订与省略记录。
修订后的全文仍需重新来源对照和独立语义复核，旧报告不能自动认证新文字。

默认主题列表及正文检索只显示每个修订系列的最新草稿。旧 ID 仍可直接阅读，文章页提供
新旧版本链接；原版本的阅读记录、作答和复习标记保留在原 ID 下，不自动认定新稿已掌握。
覆盖清单区分当前主题草稿和保留版本数，课程引用仅汇总当前版本，避免把旧问题稿的引用
冒充现用文章的覆盖情况。历史文章对象仍逐个校验，不因界面隐藏就跳过完整性检查。

## 逐份来源的遗漏检查

遗漏检查遇到同章多份原文互相串用证据时，可显式选择逐份来源检查：

```powershell
.venv\Scripts\python.exe -m wechat_decrypt_tool.course_wiki_completeness --root output/course-knowledge --article <文章ID> --model qwen3.5:9b --wait-gpu-seconds 3600 --per-source
```

每次仍读取完整章节原文，只检查其中一份来源的连续范围，文章证据限于实际引用该来源的解释。
没有对应解释的来源仍逐字符检查，不能算作已覆盖。页面按原章节汇总，链接仍跳到该章。
此策略有独立任务指纹与断点；旧配方、失败尝试、预算和历史报告不变，结果仍不代表语义验收。

## 学习记录与迁移

重复附件的 PDF 页面可通过 `course_pdf_cached_aliases.prepare(store, proof)` 核验已有 OCR，
再用 `apply(store, prepared)` 补登记。只复用当前已提交、活动片段与缓存全文完全一致的结果，
重新核对页面图片、缓存、模型绑定和保留 PDF 的完整字节摘要；不调用模型或读取原课程目录。
来源、图片或缓存变化时拒绝写入。准备结果须作为可信的固定执行输入保存，并绑定其摘要。

补登记只处理没有任何现有版本或暂存片段的目标；写入事务中的 `require_absent` 检查会再次
拒绝并发创建的目标，整批回滚，保留现有版本。再次准备时跳过已存在目标，不重复增加记录。
此操作不恢复已暂停的 PDF 作业、不刷新失败次数，也不把复用的模型转录视为人工校验或
补齐了此前没有 OCR 的原始页面。旧驱动、进度与报告继续保留，后续结果另存补充凭据。

新建证据分配可显式调用 `course_wiki_evidence.create(..., temporal=True)`，按开始时间排列
完整语音和画面原文；同一时间先放语音，再按结束时间及证据 ID 排序。时间窗口内重叠的
已保留语音记录完整纳入，每个窗口内的原文字符只分配一次。页面和规划上下文容量上限不变，
因此仍可能跨页；时间相邻不能证明内容语义对应。

这是独立版本的可选策略，默认配方、历史文件及任务预算保持不变。新旧分配均可校验、
阅读和恢复；仅更新来源指纹的刷新操作保留原策略。不得据此为已开始、跳过、失败或耗尽
预算的旧范围重新建任务。首次发布采用新策略的文章前，须重启阅读进程以载入协议支持，
不重启健康的课程处理与发布队列。

2026-11-03 对冻结的 42 节已发布笔记、1,646 个窗口进行了无模型调用的配方比较：
14,499 条窗口内证据、5,954,295 个原文字符全部保留。仅含画面的规划范围由 551 个降为
10 个，语音与画面混合范围由 1,435 个增为 1,994 个；总范围由 2,197 个变为 2,219 个。
本次没有创建新分配或规划作业，也没有证明实际文章质量改善。相关 98 个测试通过，包含
新旧策略的发布、快照与隔离恢复；另外重读了全部 43 个历史文章版本，内容保持不变。

作答、逐题自评、已读、复习标记、阅读位置存于当前浏览器的 `localStorage`。
作答不会发送给模型或服务器；已读不等于掌握，自评也不冒充自动评分。
每篇文章可导出 JSON 学习记录，也可在导航的「学习记录」页批量导出、预览和导入。
换浏览器、端口或清除浏览器数据前请先导出；不会自动跨浏览器同步。
导入仅在本机读取文件，支持旧单篇格式，最多 16 MiB、10000 个文章版本。
默认保留本机已有记录，可明确选择使用备份覆盖；未知文章版本仍保留并可再次导出。
各版本的作答与自评分开，不自动转移给新稿。预览后记录变化会拒绝导入；写入失败时
尝试回滚，若浏览器阻止恢复或其他页面并发修改，会明确报告部分记录未能恢复。
学习记录 JSON 不包含正文、图片、模型或运行环境，不能替代素材备份。

迁移 Wiki 需保留 `library/` 和 `wiki/`，源归档还需另行备份原数据库、课件、
音频及其完整清单。仅复制网页文件或文章 JSON 不能代替完整归档与恢复验证。
本阶段不允许据此删除原视频。

后续笔记可调用 `course_library_delta.save(...)`，以已验证快照或组合清单及其目录为
基线，只备份新增、修订的笔记对象、检索词表和新图片。必须提供基线清单的已知摘要；
旧式组合清单还须显式提供所需前序备份清单及摘要。后续增量会继承这条依赖链。
重复检查没有新笔记对象时不产生新备份；同一课程的修订保留旧对象和前序备份。

传入本地阅读器客户端时，会核对新笔记的实际 HTTP 内容、每个章节的检索入口及全部
图片字节。目录指针在准备时冻结；发布后继续推进不会改写已捕获的版本。输入或复制
中的对象变化、前序清单变化、来源丢失、路径越界及磁盘余量不足均拒绝完成备份，
中断的目录保留供检查，不自动覆盖或重试。默认在源盘和目标盘各保留 32 GiB。

增量目录内的 `combined-wiki-snapshot.json` 只是完整依赖清单；单独复制它或最新
增量不能恢复全部内容。须保留所有前序备份，再于新目录组合文件并独立验证阅读器。
该 API 的字节校验、章节检索和图片校验不代表独立执行或内容语义验收，也不备份
原始归档数据库、全部素材、Python 环境或浏览器学习记录；不启动模型或恢复提取任务。

## 验证

PDF 缺页可使用冻结计划的 `pdf_sources_selected_pages`，每项提供 `path`、
`source_key`、`parent_raw_digest`、原 PDF 的完整 `pages` 和非空整数列表
`selected_pages`。`summary.page_occurrences` 只统计本次选定页的出现次数；
例如完整 PDF 有 500 页，本次选择 `[101, 102]`，这两个数分别为 500 和 2。
重复页、越界页、重叠范围、矛盾来源及与旧式警告请求混用会被拒绝。

生产器只处理指定页，独立校验器要求完成页与错误页恰好构成指定范围，并继续校验
完整原件的页数、摘要、原页像素、缓存、全文索引和实际 HTTP 引用。报告以
`page_scope=selected_pages` 标明范围，不能据此宣称整个 PDF 已完成。旧式
`pdf_sources_all_pages` 仍表示全页范围，提取器版本、缓存及历史证据身份不变。
补处理时使用独立报告前缀，保留原有失败、暂停、预算与历史报告；显式指定页不代表
允许重跑此前失败或暂停的任务。

```powershell
.venv\Scripts\python.exe -m pytest tests/test_course_wiki_writer.py tests/test_course_wiki.py tests/test_course_lesson_exports.py -q

```

页面无需 CDN、远端字体、统计或外部模型。课程文字以 DOM 文本节点显示，代码以
`pre/code` 显示，不能把模型输出当 HTML 执行。图片缺失、目录未就绪、读校验失败
和检索零命中均显示明确状态。

讲义片段可以没有模型生成的知识点。增量备份仍逐节验证真实检索：有知识点时使用其
名称，否则使用该片段已有的语音原文、窗口内画面文字或摘要；必须在实际 HTTP
检索结果中找到该节，不会补造知识点或跳过无知识点的片段。没有可检索文字、检索
未命中或图片字节不符仍会拒绝完成备份，保留此前的备份与失败记录。
