# 完整课件文字的逐项关系审核

`course_textbook_whole_courseware` 对已保留的完整 Notebook 文字逐项提出关系，再由另一本机模型独立复核。
它不写文章，不改变原账本、覆盖执行器、原模型请求、失败、预算或暂停记录。
Notebook 单元只是有限调度单位，不会变成文章结构。

关系明确区分：课堂完整教过目标、具有具体教学联系的补充资料、确无有效教学的上下文、未决。
正向关系必须指向当前输入确实提供的课堂原文；每份文字记录都有必填结果键。
独立审核针对所提类型检查全部条件，任一条件为 false 即保留未决；程序不改变旧判断来获得通过。
重复、代码、短句、文件名、同主题、检索排名或文章遗漏都不能直接证明非教学或课堂关系。

完整同单元和相邻单元资料进入上下文。已有图片 OCR 仅作为明确标记的草稿上下文，七张图片的图示
语义与实际课堂关系仍需另行审核；这个文字任务的全部结果也不证明图片准确或文章覆盖。
全量 Goal 的其他课件保持原范围。

## 有限调度与输入预算

先对每个完整单元检索课堂候选，再把能完整放入请求的相邻单元合并。每请求最多四个单元，
完整提议输入最多 27,000 tokens；目标文字、相邻文字、课堂候选原文和图片 OCR 上下文均不截断。
合并后仍逐项输出与独立核对，成员分配恰好一次；单个完整单元无法放入时直接停止，不裁剪原文。

第二课实际准备了 67 个单元、84 条完整文字、31,815 字符，合并为 25 批、50 个原始模型角色。
每角色最多两次结构尝试、0 次额外语义循环。50 是计划角色数，结构失败可能产生第二次尝试，
不能当作模型实际调用总数或已完成数量。合并前按单元执行会有 134 个角色；目前没有同输入耗时
对照，不据此宣称提速倍数或全课完成时间。

完整输入和留足候选字段的容量预检均通过，最大预检输入 27,128 tokens、配置 context 32,768。
实际执行继续按真实请求计数，独立校验服务端完整输入、结束原因、GPU 驻留和实际解码 schema。
当前 41 项相关回归及 Ruff 通过，包含完整记录、合并上下文、必填范围、独立负面结果、GPU 回执、
缓存篡改、零推理复用、双次额度耗尽和活跃守护拒绝；合成收据只用于测试，不冒充真实模型执行。
