# 整课原文覆盖核验

`course_textbook_whole_coverage` 接受已经退出、确实完成组装的完整原记录稿件。它先通过
`course_textbook_whole_snapshot` 或 `course_textbook_whole_continuation` 重建原账本、完整请求、
实际模型及 GPU 回执、正文、图、整篇阅读审核和全部未决问题。局部快照不能分配整课覆盖额度。
冻结的旧模块不修改，健康的作者、来源抽取和 PDF 队列不重启。

## 保留范围与减少重复

所有完整原记录都以原字符、偏移和 SHA 分配到分句，每个分句恰好出现一次。每批最多 256 分句，
不截短完整目标原文、相邻语境或任何正文条目。正文包括实际导入、前置说明、正文段落、解释图和
小结；自测答案不用于替代缺失教学。正文能完整放入本次输入时只用一个块，否则按实际 token
容量保留全部完整条目，先查引用相关条目，未解决分句继续查询其他正文块。

同一来源里连续、同判断、同依据的分句允许共用一份输出说明，程序仍展开到每个分句并逐项保存
去向。跨来源合组、不连续合组、遗漏、重复、虚构原文编号或文章位置均拒绝。组中任意成员缺少
条件、例子、步骤或限制，都不能把整组算覆盖。

本次第二课实测有 587 份完整来源、274,804 字符、15,534 个无损分句。旧入口仅按来源与每批
12 分句划分就至少有 1,589 个请求分区，还未计算反复查找正文窗口。新分句批次的理论下限为
61；这不是实际请求数量，完整正文容量、模型合组方式和复核分组仍会增加调用。实际计划必须
等完整成稿后生成，尚无相同输入的实测提速比例。

## 两种独立角色

`course-defiant:q4` 提出 covered、missing 或 non_teaching 分组。`qwen3.5:9b` 独立核对该组的
每个成员、全部完整原文和真实正文位置；每次最多复核 16 组。任何成员不成立即拒绝整组。
审核员不能把候选理由、账本判断或其他组的通过当事实。两种角色均绑定本地模型 SHA、真实请求、
解码 schema SHA、完整 GPU 输入/输出回执与原两次结构尝试上限；不增加语义修订循环。

已出现教学疑点的分句不能在后续正文块里通过改成“非教学”消失。被账本确认含教学的来源如被
全部排除，会单列分类冲突。所有未决判断、负面审核及原稿问题保留。即使自动覆盖全部完成，
`semantic_accuracy_verified`、`reader_publication_allowed` 和 `source_deletion_allowed` 仍为 false；
课件关系、事实与编辑验收、自测和用户验收另行完成，不直接发布或删视频。

实际输入目标为 42,000 token，候选输出最多 12,288，独立复核输出最多 8,192，模型 context
上限 65,536。单条完整原文或正文确实无法容纳时停止并明确保留断点，不以截断规避限制。

## 执行与恢复

完整作者作业内绑定 `whole-manuscript-coverage-execution.json`。覆盖作业位于
`wiki/whole-manuscript-coverage-jobs/<作业ID>/`，保存完整计划、实际快照、各阶段尝试与原始
模型回执、逐批私有结果、整课私有覆盖结果和失败记录。更换父稿、模型、计划或代码不能刷新
同一父稿的覆盖额度。进度在 `wiki/whole-manuscript-coverage-current.json`。

可使用 `prepare` 只认证输入与登记原额度，或通过 `guard` 运行有限核验。原作者尚在运行时使用
`after-writer`，必须明确指定原作者与原温控守护的 PID 和创建时间。观察器每 10 秒核对同一身份，
不重启它们；仅在完整作者和原守护都真实成功退出后，认证完整稿件，再启动一次有温控的覆盖任务。
原任务失败、进程身份改变、暂停标记或 supervisor-stop.flag 均停止接续，不自动热恢复。

沿用共享 GPU 锁、200W 保护上限、70°C 暂停和两盘各 32 GiB 保留空间。输入、逐批与最终证据
增量复制到 `Documents/CourseKnowledgeBackups/whole-manuscript-coverage/<作业ID>/`；它们不是完整
模型环境备份。输出到终端的只有状态、数量、ID、SHA 和路径，不包含原文、正文或审核理由。
