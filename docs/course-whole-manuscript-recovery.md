# 整课稿件核验与原角色结构修订

`course_textbook_whole_snapshot` 为新版完整原记录写作提供只读入口。`prefix` 只认证当前实际处理完的
前缀，不将其发布为文章；`complete` 只接受已经退出且确实组装完成的 worker，并取得原写作排他锁。
两种方式均重建完整父账本、原计划、实际写作分配、真实请求、模型身份、GPU 回执和原恢复凭证，
不调用模型、不生成缺少的缓存、不刷新预算。

完整入口还必须重建每个小节的一次必要语义修订、非教学排除、整篇阅读审核、实际正文组装、全部
未决问题、阅读投影及 HTML。返回的是供后续覆盖复核使用的私有稿件，语义验收和阅读发布继续为 false。
当前真实核验只完成第二课前 7/16 单元；整篇路径已作合成回归，不能当作真实整篇已经完成。

快照保存于 `wiki/whole-manuscript-snapshots/<凭证SHA>.json`，只输出状态、数量、SHA 与路径。
原文、审核理由及内部正文不输出到工具或对话。快照不是旧版 composition 覆盖任务，后续全原文
覆盖执行器仍须接入新版整课清单，不能拿局部核验替代完整覆盖。

第二课随后停于第八单元 `section-0007-write`：两次原候选均含实际输入未提供的引用，因此继续拒绝。
它们不能沿“实际已提供相邻原文”的适配放行，不能删除这些引用或改写正文后假称原写作通过。
真实请求使用 `oneOf` 教学/非教学分支；冻结的旧 `evidence_schema` 不遍历该分支，其 5 处引用字段
均未获得范围 enum，这是重复发生引用错误的一项实际程序原因。

`course_textbook_schema_scope.bind` 是显式使用的新 schema 函数，可遍历 oneOf/anyOf/allOf、数组、
定义和条件分支，为引用施加实际证据包的编号范围。其他约束、非教学分支、无代码时的空引用、
共享 schema 别名以及字面量数据均保留。它不会修改冻结旧函数，不能反向改变已用请求或重新分配额度。

`course_textbook_whole_unit_repair` 只使用该单元原来未用的 `review`、一次 `repair` 和 `repair-review`：

- 先认证两次原写作请求及完整真实响应，固定最早完整候选，原文和元数据均不改。
- 将它明确作为不可信审核输入，保留全部 49 份原依据及实际已经提供的 3 份相邻原文，共 52 份。
- 使用原独立审核角色，再执行唯一的结构修订；即使初审认为事实通过，也必须修正机器已确认的结构问题。
- 修订请求保留完整候选、所有原分配知识及全部原审核意见；修订 schema 明确约束分支中的引用。
- 修订后再次独立审核。负面结果完整保留；每个阶段仍最多两次结构尝试，没有额外写作或语义循环。

执行契约为原作业内 `<单元>-whole-original-role-repair-execution.json`，结果为
`<单元>-whole-original-role-repair-result.json`。不创建假的 `<单元>-write.json`，也不将单元结果
直接算为整篇组装。后续必须用能认证实际角色及派生关系的接续入口回到全稿，旧快照不会自动接受新派生。
当前有限修订本身不发布文章、不授予全课覆盖、课件关系、编辑、测验或用户验收。

GPU 入口使用受支持的 `wiki-revision-thermal-guard`，200W 保护上限、70°C 暂停且不自动恢复，
两盘各保留至少 32 GiB。旧停止/失败/暂停和原守护终态都保留，不重启健康 PDF 或抽取进程。
输入与结果增量保存在 `Documents/CourseKnowledgeBackups/whole-original-unit-repair/<文章作业>/<单元>/`；
这些副本不能冒充完整模型环境或全部知识库恢复。
